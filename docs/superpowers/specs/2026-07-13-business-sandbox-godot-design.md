# 创业沙盘 — Godot 2D 全栈实现设计文档

> 基于 PDF 创业沙盘规则，复刻一款 2D 商战模拟游戏。
> 关联项目：Mock-Court（模拟仲裁庭），复用其 Rust API / Next.js 多 Agent 基础设施。

---

## 1. 项目概述

**项目名称**：创业沙盘（商业全价值链模拟器）

**目标**：基于 PDF 沙盘规则，使用 Godot 2D 前端 + Rust 后端 + Next.js AI Agent 架构，复刻一款多公司在竞争环境下进行 11 年经营推演的商战模拟游戏。

**核心交互**：点击式操作，后端实时处理复杂财务和制造逻辑，前端展示直观的图文状态。

### 与现有项目的关系

该项目是对现有 Mock-Court 项目的能力扩展：
- **复用**：Rust API 的基础设施（网络框架、状态管理）、Next.js 多 Agent 编排能力
- **新增**：商业沙盘游戏逻辑（全新的领域）、Godot 2D 前端（替换 Next.js 前端）
- **共存**：仲裁庭业务线保留，通过运行时配置切换领域

## 3. 核心游戏循环与状态机

### 3.1 时序逻辑（基于 PDF P.10）

Rust 后端维护唯一完整的游戏状态。前端职责：接收状态并渲染 → 接收用户输入并发送。

**年度流程：**

1. **年初**
   - 玩家决策：市场投资、长期贷款、买/租工厂、拟定竞标策略
   - 发送决策数据给 Rust

2. **季度运营（循环 4 次）**
   Rust 按顺序执行以下步骤，每步向前端推送状态更新：
   1. 更新应收账款
   2. 更新短期贷款利息
   3. 产品研发进度推进
   4. 供应商交货/付款
   5. 新原料订单处理
   6. 更新生产线状态
   7. 产线建设/转产
   8. 新生产/付费
   9. 订单交付
   10. 支付行政管理费

3. **年末**
   - 支付产线维护费
   - 计提 20% 固定资产折旧
   - 支付长期贷款利息
   - 缴纳所得税
   - 生成年度财务报表

### 3.2 游戏阶段（对应 PDF 章节）

| 阶段 | 年份 | 主题 | 核心机制 |
|------|------|------|---------|
| 第1节 | 第1-4年 | 适应期 | 单项产品起步，手工/半自动线，学习规则 |
| 第2节 | 第5-7年 | 市场竞争 | 多产品线，BCG 矩阵，ABC 成本法，差异化策略 |
| 第3节 | 第8-11年 | 高阶经营 | 杜邦分析，ROE/EVA 考核，公司估值 |
| 第4节 | 反思复盘 | - | 现金流分析，商业模式评估，团队效率总结 |

## 4. Godot 2D UI 结构

### 4.1 整体布局（顶部-中部-底部-弹出层）

#### A. 顶部状态栏 (`Control` 锚定 Top)
- **左侧**：年份（`Label`）、当前季度（`TextureRect` 图标或文字）
- **右侧**：现金流（金币图标 + 数值）、总资产、总负债

#### B. 中部核心经营区
4 条水平生产线垂直排列（`VBoxContainer`），每条为一个 `ProductionLine` 自定义节点：
- **左侧**：产线名称（手工线/半自动/全自动）
- **中部**：`TextureProgressBar` 或 5 个 `TextureRect` 占位符轨道，标记在产/停工/转产中/建设中
- **右侧**：原料输入槽（桶标志）和成品输出槽（小车标志）

#### C. 底部财务与操作区（`GridContainer`）
- **银行卡池**：4 个长贷槽位（1-4年）+ 4 个短贷槽位（1-4季），不同颜色金币堆叠
- **操作按钮**：
  - "下一年初开会"
  - "下一季度执行"
  - "查看年度报告"
  - "紧急贴现（弹窗确认）"

#### D. 独立弹窗系统
- **年度报告弹窗**：损益表 / 总资产表 / 费用表 / 负债与股东权益表（四标签页，可滑动）
- **订货会弹窗**：市场预测图 + 广告费输入 + 订单卡选择（产品/批次/单价/账期）
- **贴现确认弹窗**："手续费为应收账款 1/14 取整，是否确认？"
- **破产弹窗**：黑色遮罩 + 游戏结束原因

### 4.2 自适应策略
- 启用 `Stretch` 模式
- 使用 `Control` 节点的容器布局（`HBoxContainer` / `VBoxContainer` / `GridContainer`）
- 确保窗口缩放时控件按比例自适应

## 5. 通信协议

### 5.1 WebSocket 连接
- Godot 客户端连接 Rust 服务器的 WebSocket 端口
- 全双工 JSON 通信
- Godot 端 `WebSocketManager` 单例管理连接

### 5.2 状态推送 JSON 格式

```json
{
  "game_year": 2,
  "game_quarter": 3,
  "cash": 32000000,
  "long_term_loans": [
    {"year": 1, "amount": 20000000, "status": "active"},
    {"year": 2, "amount": 40000000, "status": "active"}
  ],
  "accounts_receivable": [
    {"amount": 36000000, "due_quarter": 2}
  ],
  "factories": [
    {
      "id": "old_factory",
      "capacity": 4,
      "lines": [
        {"id": 1, "type": "manual", "product": "奔马", "status": "idle", "progress": 0},
        {"id": 2, "type": "fully_auto", "product": "none", "status": "building", "progress": 3}
      ]
    }
  ],
  "product_rd": {
    "飞鹰": { "status": "in_progress", "progress": 4, "total": 6 }
  },
  "message": "季度执行完毕，扣除行政管理费1M"
}
```

### 5.3 事件推送
- `{"event": "game_over", "reason": "cash_flow_break"}` — 游戏结束
- `{"event": "quarter_complete", ...state}` — 季度执行完毕
- `{"event": "year_end", ...state}` — 年末结算
- `{"event": "ai_bids", "competitors": [...]}` — AI 对手竞标策略

## 6. 核心游戏规则（硬编码至 Rust 后端）

| 规则 | 说明 | 前端表现 |
|------|------|---------|
| **贴现** | 手续费为应收账款 1/14 取整 | 弹窗确认提示 |
| **产线转产** | 全自动线 2 季度 4M，半自动 1 季度 1M，手工 0 成本 | 倒计时显示 |
| **固定资产折旧** | 年底产线资产价值强制减少 20% | UI 数值更新 |
| **破产判定** | 股东权益 < 0 或现金流断裂 | 黑色遮罩 + 冻结操作 |
| **季度管理费** | 每季度扣除 1M | 现金数值实时更新 |
| **所得税** | 年度利润按税率缴税 | 年度报表显示 |

## 7. 实施路线图

### 阶段 1：地基（UI 骨架 + WebSocket 通信）
- Godot：搭建 MainGame 核心场景，三区域布局
- Godot：`WebSocketManager` 单例，连接 `127.0.0.1:8000`
- Rust：简单 WebSocket 回声/测试服务端
- 验证：UI 节点能根据 JSON 改变文字

### 阶段 2：财务与时间循环
- Rust：实现时序引擎（年初→4季度→年末）
- Rust：核心财务计算（现金流、贷款、折旧、税务）
- Godot：各 UI 面板绑定状态更新函数
- 验证：点击"下一季度"，现金减少 1M，状态面板同步更新

### 阶段 3：AI 对手接入
- Next.js：实现 5 个 AI 竞争对手的多 Agent 编排
- Rust：接收 AI 竞标策略并融入游戏逻辑
- Godot：市场面板展示 AI 对手状态（激进/稳健/破产）

### 阶段 4：动态资产动画
- 将占位符色块替换为贴图
- 用 `Tween` 动画实现原料→产线→成品的流动效果
- 发布：Web (HTML5) + 桌面双端构建
